# Bapu v0.1 方案

状态：草案，待用户确认（2026-11-04）。验证过的流程、参数和数字见 `pipeline-notes.md`。
本文不含任何歌词文字；示例里的字都是虚构的。

## 1. 分层

```
前端 web/（浏览器） ──HTTP / SSE──▶ 后端 bapu.server（FastAPI） ──函数调用──▶ 核心库 bapu
                                                                     ▲
                                           CLI（bapu run …） ────────┘
```

- **核心库**：各步骤、缓存、模型注册表、乐谱 JSON、修正、报告、导出。不知道前端存在。
- **后端**：薄的一层 API，不重复写业务逻辑；只监听 `127.0.0.1`。
- **前端**：独立目录 `web/`，只通过 API 通信，可以单独开发、单独替换。
- **SV Agent Bridge**：不是依赖。只在开发时由 Claude 通过 MCP 做集成验证或导入；Bapu 代码和测试都不连 Bridge。

每一步都是一个可以直接调用的函数，接收 `backend`（来自模型注册表）、参数和进度回调。CLI 和 API 调用同一组函数。

## 3. 模型注册表

每条记录：

- 所属步骤（分离 / 主唱 / 去混响 / 转谱 / 对齐）、模型 ID、显示名称、后端实现（audio-separator、SOME、MMS…）
- 下载来源、文件大小、SHA-256
- 许可证（名称、链接、是否允许商用）
- 大致显存需求
- 验证状态：`verified`（在验证歌曲上复现过笔记里的数字）或 `experimental`

规则：

- 权重存在 `.cache/models/<步骤>/<模型ID>/`。
- 下载前必须显示许可证并由用户确认；支持断点续传；下载后校验 SHA-256，不通过就不启用。
- 只能下载注册表里的模型，不接受任意网址。
- 同一类模型换权重：只加注册表记录。全新一类模型：先写适配器，实现该步骤的接口。
- 起步时注册表只放这次验证过的那一套。

CLI：`bapu models list`、`bapu models pull <id>`、`bapu models rm <id>`。

## 4. 命令行

```
bapu run <音频> --lyrics <文件> --lang yue [--out work/<名字>] [--from align] [--set assign.gap_pen=0.4] [--model align=mms-1b]
bapu status <out>                          # 每一步是否最新、耗时、用的模型、关键数字
bapu export <out> --format mid,svp,paste
bapu corrections from-svp <out> <file.svp> # 把在 SV 里改过的地方读成修正
bapu eval <out>                            # 和已确认的句子对比（例如 L10 10/10）
bapu models list | pull <id> | rm <id>
bapu serve [--port 8765]                   # 启动后端和前端（M4 起）
```

## 5. 缓存

- 工作目录按编号分子目录 `01_separate/ … 08_assign/`，另有 `score.json`、`review.md`、`review.json`、`corrections.yaml`、`export/`。
- 缓存键 = 输入文件指纹 + 这一步的参数 + 模型 ID + 这一步的代码版本号。任一项变了就从这一步重跑，否则跳过。
- 默认输出到 `work/`（已在 `.gitignore`）。

## 6. 乐谱 JSON（`bapu.score/1`）

- 文件头：音源指纹、拍速（BPM、第一拍、置信度）、拍号、每一步用的模型 ID。
- `lines[]`：时间、语言、对齐置信度、使用的版本（自动 / 人工）。
- `notes[]`：编号从 1 开始；时间用秒；整数音高加音分偏差。
  - `kind`：`word` / `sustain`（`-`）/ `cont`（`+`）。
  - 另有 `lyric`、`lang`、`line`、`conf`（对齐置信度和起音证据）、`flags`（如"自动合并"）。
- 全部用秒存，导出时再换算成 tick 或 blick，不做量化。

## 7. 修正文件 `corrections.yaml`

- 只有用户编辑（手改或在前端改），程序生成的结果永远不覆盖它。前端写入时保留注释，并用版本号防止覆盖别处的修改。
- 按时间定位（音符起点，容差 30 ms），不按编号；上游重跑导致编号变化后照样能套上。
- 套不上的修正进审查报告，标为"失效"，不会被悄悄丢掉。
- 类型：确认 / 拒绝合并；某句哪些音符是 `-`；锁定某句用人工版本；修改音高、拍速、某句语言；字幕错字（含歌词文字，只留在本地）。
- `from-svp` 解析用户保存的 `.svp`，和计划对比后生成修正。

## 8. 审查报告

`review.md` 和 `review.json`，只写时间（mm:ss.xx）、音符编号、句号、置信度和状态：自动合并的音符、`-` 的位置、低置信度的句子、音节数和音符数对不上的句子、失效的修正。

## 9. 导出器

- **MIDI**：单轨，带拍速、拍号和每个音符的歌词事件（含 `-` 和 `+`）。
  - 测试里用 Python 读回自检；集成验证时由 Claude 用 Bridge `inspect_score_file` 检查并导入临时音符组回读核对。
  - 中文歌词事件的编码要实测。
  - Bridge 导入最多 512 个音符，且不会套用 MIDI 拍速，需另调 `set_time_axis`。
- **`.svp`**：分三步，每一步都请用户在 SV 里打开确认：1) 空工程 2) 1 个音符 3) 整首歌。
  - 时间单位 blick（每个四分音符 705600000）；每个音符写歌词和 `languageOverride`；歌手留空。
  - 加一条伴奏音频轨，只引用绝对路径，不复制音频。
- **paste**：保留"一句一行"的粘贴文件作为后备。

## 10. 后端 API（M4）

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/jobs` | 上传音频和歌词，选语言、每一步的模型和参数，建任务 |
| `GET` | `/api/jobs`、`/api/jobs/{id}` | 任务列表、任务详情（每一步状态、耗时、模型、关键数字） |
| `GET` | `/api/jobs/{id}/events` | SSE 进度 |
| `POST` | `/api/jobs/{id}/rerun` | 从某一步重跑，可带参数或换模型 |
| `GET` | `/api/jobs/{id}/score`、`/review` | 乐谱 JSON、审查报告 |
| `GET` | `/api/jobs/{id}/audio/{stem}` | 原曲、人声、伴奏，支持 Range 请求 |
| `GET` / `PUT` | `/api/jobs/{id}/corrections` | 读写修正（带版本号） |
| `POST` | `/api/jobs/{id}/corrections/from-svp` | 上传 `.svp` 生成修正 |
| `POST` / `GET` | `/api/jobs/{id}/export` | 生成并下载 MIDI、`.svp`、粘贴文件 |
| `GET` | `/api/models` | 模型列表（按步骤分组、下载状态、许可证、验证状态） |
| `POST` | `/api/models/{id}/pull` | 下载（必须带 `acceptLicense: true`），SSE 推进度 |
| `DELETE` | `/api/models/{id}` | 删除已下载的权重 |
| `GET` | `/api/system` | 显卡、显存、磁盘空间 |

- 只有一张显卡：同一时间只跑一个任务，其余排队；失败后可以从断点继续。
- 日志不写歌词文字，只记时间和编号。

## 11. 前端（M5）

技术：Vite + React + TypeScript；波形用 wavesurfer.js；钢琴卷帘用 Canvas 自己画。

页面（2026-11-05 改成一首歌一条流程，用户按顺序往下走）：

没有任务列表和模型页，顶部只有一条步骤条：原曲 → 参考歌词 → 语言 → 自动处理 → 审查 → 导出。
每一步一页，带“上一步 / 下一步”。同一时间只显示一个工程；右上角“新建 / 打开”回到第一步。

1. **原曲 / 工程**：选原曲（系统对话框，拿到真实路径；也可以拖进页面），再选工程文件夹（默认原曲旁边的
   `<歌名> - Bapu`），建好 `<歌名>.bapu`。这一页也能“打开工程…”（选 .bapu）和打开最近的工程。
   工程文件夹自带输入和全部结果，可以移动；`bapu open` / 双击 .bapu（`bapu register` 后）直接打开。
2. **参考歌词**：可选；没有就直接下一步。
3. **语言**：粤语 / 普通话 / 英语多选；“开始处理”就跑流程。
4. **自动处理**：总进度条 + 九个步骤，正在跑的一步显示转圈，跑完的显示一句结果。
   不提供“从某一步重跑”：每一步只有一个模型，改设置后缓存会决定哪些步骤要重算。
   第一次缺模型时，这一页先列出要下载的模型（大小、许可证、手动下载地址），
   一次接受许可证后下载，下完自动开始。不在界面上选模型；命令行 `--model` 和 API 的 `models` 仍可替换。
5. **审查**：波形 + 钢琴卷帘 + 审查条目列表；点条目跳到对应时间试听；确认 / 拒绝合并、改 `-` 位置、锁定人工版本，写入修正后只重跑后面的步骤。
6. **导出**：生成并下载 MIDI、`.svp`、粘贴文件；列出上次导出的文件，导出后乐谱改过会提示；上传在 SV 里改过的 `.svp` 生成修正。

桌面窗口（2026-11-05）：`desktop/` 是 Tauri 2 外壳（Rust 只做启动和窗口），在后台用 `.venv` 启动
`bapu serve --parent-pid`（随机端口），窗口里显示同一套网页；关窗口或窗口崩溃时服务都会退出。系统对话框和外部链接
走 Tauri（dialog、opener 插件），在浏览器里时仍走 `/api/dialog`。只开一个窗口：再双击别的 `.bapu` 会在原窗口打开。
后端不改用 Rust：模型和前后处理都是 Python 生态，重写要重新验证全部结果，速度也不会变快。

便携版（2026-11-05）：`scripts/build_portable.py` 生成约 40 MB 的程序文件夹。第一次启动时程序自己部署 Python 推理环境：
检测显卡，选 PyTorch（CUDA 12.8 / Intel XPU 实验 / CPU），用自带的 uv 把 Python 3.12 和 uv.lock 里钉死的包装进 `runtime/`
（不建 venv、不写注册表、不进 PATH，下载缓存装完就删）。流程最前面加了“环境”一步：推理设备、模型下载、可选的 .bapu 关联。
实测（RTX 5090）：装环境 4 分钟；在便携环境里跑同一个 MP4，341 个音符和开发环境完全一致；把 runtime 复制到别处也能直接用。
推理设备统一由 `bapu.device.pick()` 选：cuda（含 ROCm 版 torch）/ xpu / mps / cpu；只有 CUDA 验证过。

模型的删除、校验只在命令行（`bapu models list / info / rm`）。

设计稿：见 Claude Artifact「Bapu 前端设计」。

## 12. 实施顺序（每个阶段先复现笔记里的数字才算完成）

- **M1**（已完成）：骨架、缓存、进度回调、模型注册表（下载 + 校验 + 许可证）、分离 / 主唱 / 拍速 / 转谱。目标：353 个音符，没有重叠；拍速 125 BPM（原记录的 123 是量化假象，见笔记 §3）。
- **M2**（已完成）：合并 → 解析歌词 → 对齐 → 分配 → 乐谱 JSON、审查报告、修正文件，以及 `corrections from-svp`、`eval`。目标：合并后 345 个音符；L10 10/10、L02 18/20；最终字序和字幕完全一致。
- **M3.5**（已完成，用户决定）：听写为主、参考歌词为辅。新步骤 `06_dictate`（Qwen3-ASR），`07_lyrics` 改为融合，`08_align` 用录音决定补字和换字。
- **M3**（已完成）：MIDI 导出（已通过 Bridge 导入验证）；`.svp` 导出（空工程、单音符、整首都在 SV 里打开确认，带伴奏和主唱干声两条音频轨）；粘贴文件。
- **M4**（已完成）：后端 API 和任务队列，配 API 测试。`bapu serve` 只监听本机；接口另加了 `/api/stages`（步骤和默认参数，给前端建表单用）和 `/api/jobs/{id}/lyrics`（任务建好后再上传参考歌词）。
- **M5**（已完成第一版）：`web/`（Vite + React + TypeScript，wavesurfer.js，自绘钢琴卷帘）。任务、进度（SSE）、审查（播放、卷帘、条目、改类型 / 合并 / 锁定句子后保存并重跑）、导出（含 from-svp）、模型（许可证确认、下载进度）五页；`bapu serve` 直接提供构建好的界面。

单元测试只用虚构歌词。整首歌回归测试读仓库外的验证数据，数据不在时自动跳过。
